# Architecture Decision Records

An ADR records **one decision**: why it was needed, what was considered, what was chosen, and what it costs.

## Rules used in this repo

1. **One decision per record.** If the title needs the word "and", it is two records.
2. **Write it when the decision is made**, not after the system is built. A record written afterwards is a justification, not a decision.
3. **Consequences are mandatory.** A record without consequences is marketing.
4. **Records are immutable.** A decision is never edited; it is superseded by a new record that links back to it.
5. **Status is explicit:** `Proposed` → `Accepted` → `Superseded by ADR-NNNN` / `Deprecated`.
6. **Record the dissent.** If someone disagreed, their argument goes in the record. It is the most useful paragraph three years later.

## Naming

`NNNN-short-decision-in-the-imperative.md` — e.g. `0001-record-architecture-decisions.md`.
